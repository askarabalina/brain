# brain

Личная база знаний, которую читают Claude Code, Gemini CLI и другие ИИ-клиенты.

Папка `brain/` — обычные markdown-файлы: кто я, чем занимаюсь, что за проекты,
какие решения приняты и почему. GitHub показывает их как читаемые страницы,
так что база открывается с любого устройства даже без всякого ассистента.

`src/brain_mcp/` — MCP-сервер, через который клиенты в эту папку заглядывают.

## Что здесь не хранится

**Задачи.** Источник правды по ним — Execution Hub, он подключается отдельным
MCP-сервером. Если скопировать задачи сюда, через неделю будет две версии
правды. База знаний хранит то, чего в Execution Hub нет: почему решения приняли
такими, на ком застряли блокеры и когда их последний раз двигали.

## Установка

Нужен Python 3.11 или новее.

```bash
git clone https://github.com/askarabalina/brain.git
cd brain
python3 -m venv .venv
source .venv/bin/activate          # Windows: .venv\Scripts\Activate.ps1
pip install -e .
```

Проверка — сервер должен запуститься и ждать ввода (`Ctrl+C` чтобы выйти):

```bash
.venv/bin/python -m brain_mcp
```

## Подключение

Подставь свой путь вместо `/путь/к/brain`.

**Claude Code** — один раз, для всех проектов:

```bash
claude mcp add --scope user brain -- /путь/к/brain/.venv/bin/python -m brain_mcp
```

**Gemini CLI** — `-s user` обязателен: без него сервер пропишется только для
текущей папки и будет виден, лишь когда `gemini` запущен изнутри неё.

```bash
gemini mcp add -s user brain /путь/к/brain/.venv/bin/python -m brain_mcp
```

Разделитель `--` здесь не нужен: с ним CLI печатает справку и ничего не делает.

При первом запуске Gemini спросит, доверяешь ли ты папке. Пока не подтвердишь,
серверы числятся как `Disabled` и инструменты не загружаются.

### После добавления — перезапустить клиент

**Серверы читаются при старте.** Команда `mcp add` правит конфиг, но текущая
сессия его уже не перечитает: `/mcp` не покажет `brain`, пока клиент не
перезапущен. Выйди и запусти заново.

Проверка: в Claude Code набрать `/mcp` — сервер `brain` должен быть в списке
с шестью инструментами. Затем спросить обычным текстом «что ты про меня знаешь».

Если клиент отвечает по делу, но говорит, что читал файлы напрямую, — значит
перезапуска не было: он нашёл `brain/` как обычную папку, а не через MCP.

### Execution Hub

Подключается рядом, отдельным сервером — тогда клиент видит и базу знаний,
и живые задачи. Адрес и токен берутся в настройках Execution Hub.

```bash
claude mcp add --scope user --transport http execution-hub <URL> \
  --header "Authorization: Bearer <ТОКЕН>"
```

Токен — секрет: он живёт в конфиге клиента, не в этом репозитории.

## Инструменты сервера

| Инструмент | Что делает |
|---|---|
| `whoami` | профиль, люди, список карточек проектов |
| `list_projects` | какие карточки есть |
| `get_project(name)` | карточка проекта целиком |
| `search_memory(query, project?)` | поиск по базе, возвращает файл и строку |
| `save_note(text, project, source)` | запись в хронологическую ленту |
| `save_session_summary(...)` | итоги сессии отдельным файлом |

Записывающие инструменты требуют указать источник — `встреча`, `чат`, `сессия`
или `ручной ввод`. Без него запись не сохраняется: через полгода невозможно
понять, чему верить, если не видно, откуда факт взялся.

## Навыки и субагенты

Лежат в репозитории, чтобы версионироваться вместе с базой, а клиенты читают
их из домашней папки. Связываются симлинками — правишь в репозитории, работает
везде:

```bash
mkdir -p ~/.claude/skills ~/.claude/agents
for s in skills/*/; do ln -sfn "$(pwd)/$s" ~/.claude/skills/"$(basename "$s")"; done
ln -sfn "$(pwd)/agents/protokol-vstrechi.md" ~/.claude/agents/protokol-vstrechi.md
```

| Что | Зачем |
|---|---|
| `skills/razbor-ts` | разбор ТС закупки на требования, со сведением по всем закупкам |
| `skills/snimok-zadach` | офлайн-копия состояния задач в `snapshots/` |
| `skills/obnovit-funktsional` | обновление карточки функционала продукта |
| `skills/zapolnit-bazu` | заполнение пустых мест в базе разговором, не анкетой |
| `skills/otchet-razrabotki` | сводка по разработке из GitHub за период |
| `skills/proverit-reshenie` | пять способов найти дыры в плане или документе до запуска |
| `skills/razobrat-dokument` | вытащить из docx/pdf/xlsx то, что должно попасть в базу |
| `skills/transkribirovat` | запись встречи → текст с разделением по говорящим |
| `agents/protokol-vstrechi` | протокол из транскрипта встречи; без доступа в Hub и в базу |

После добавления симлинков клиент нужно перезапустить.

## Разработка и GitHub

Код читается прямо из GitHub — через его собственный MCP-сервер, своего кода
для этого не нужно:

```bash
claude mcp add --scope user --transport http github https://api.githubcopilot.com/mcp/ \
  --header "Authorization: Bearer <ТОКЕН>"
```

Токен (personal access token) — секрет. Он живёт в конфиге клиента, не в этом
репозитории и не в справочнике личных данных.

`brain/repos.md` держит то, чего GitHub про себя не знает: какой репозиторий
к какому проекту относится, кто его ведёт, и какой ник в GitHub какому человеку
соответствует. Без последней таблицы сводка по разработке не сходится
с задачами Execution Hub.

Коммиты, пулл-реквесты и ревью в базу не переносятся — они читаются из GitHub
живьём, как задачи из Hub.

**Сводка** — навык `otchet-razrabotki`: «что делала команда на этой неделе»,
«что висит на ревью по DLP». Главный раздел в ней — «застряло»: открытые
пулл-реквесты старше недели и ветки без движения, с указанием, от кого ждут
ответа.

## Функционал продуктов

`brain/products/<продукт>.md` — что продукт умеет на сегодня. Отвечает на
вопрос «а у нас есть X»: в разговоре с заказчиком, при разборе ТС закупки,
при планировании доработок.

Отдельно от `brain/projects/`, потому что это разные вещи с разным ритмом:
карточка проекта меняется, когда принято решение, карточка продукта — когда
вышел релиз. И читают их для разного.

| Статус | Что значит |
|---|---|
| `есть` | работает в выпущенной версии, можно обещать |
| `частично` | работает с оговоркой, оговорка обязательна |
| `в работе` / `план` | делается / решено делать |
| `нет` | не делаем |
| `уточнить` | по умолчанию, пока не подтверждено |

Идентификаторы строк общие с `skills/razbor-ts/categories.md`: разбор ТС
закупки берёт колонку покрытия из карточки, а не спрашивает заново.

**Обновление** — навык `obnovit-funktsional`: по релизу, по ходу разговора или
по запросу «обнови функционал DLP». Статус повышает только человек, даже если
задача в Hub закрыта. Карточка старше трёх месяцев помечается как возможно
неактуальная.

Новый продукт — скопировать `brain/products/_шаблон.md`.

## Документы

Документы по проектам — docx, pdf, xlsx, pptx — **в репозиторий не кладутся
и в markdown не переписываются**. Они остаются там, где лежат; в базу идёт
вывод из них, а не содержимое.

Переписанный в markdown документ — это худшая копия оригинала: искать по ней
неудобно, источником правды она не становится, а в репозиторий заодно утекает
то, чему там не место — данные клиентов, результаты аудитов, персональные
данные.

`brain/documents.md` — указатель: какой документ существует, на какой вопрос
отвечает, где лежит, разобран ли. Колонка «на какой вопрос отвечает» важнее
названия файла: по `ТЗ_финал_v3_правки.docx` не найдёшь ничего.

**Чтение.** Если клиент не открывает формат сам:

```bash
pip install -e '.[documents]'
.venv/bin/python scripts/v_tekst.py путь/к/файлу.docx
```

Понимает `.pdf`, `.docx`, `.xlsx`, `.pptx`, `.csv`; с `-o <папка>` пишет `.txt`
рядом. У PDF проставлены номера страниц, у таблиц и листов — заголовки, чтобы
на извлечённый факт можно было сослаться. Промежуточные `.txt` в git не
попадают.

**Разбор** — навык `razobrat-dokument`: извлекает решения с причинами, связи,
возможности продукта и роли людей; не извлекает пересказ, таблицы целиком
и цифры, которые устареют. Черновик показывается до записи.

Начинать стоит не с самого большого документа, а с того, к которому
возвращаются, и только по активным проектам.

## Телеграм

Бот над той же базой: спросить с телефона, продиктовать заметку голосом.
Настройка и конфиг — в [`telegram/`](./telegram/README.md).

С телефона доступно **только чтение** Execution Hub — не правилом в промпте,
а списком `enabledTools`: незарегистрированный инструмент модель вызвать
не может. Справочник личных данных туда тоже не попадает. Разрешена одна
запись — заметка в базу, она идёт в git и её видно.

Подписка Claude Max доступа к API не даёт: боту нужен отдельный ключ
провайдера. Подробности и расходы — в том же README.

## Записи встреч

Запись → расшифровка с разделением по говорящим → протокол. Всё на машине
пользователя: записи встреч содержат то, что по «Границам» нельзя выносить
наружу, поэтому облачные распознавалки не используются.

```bash
.venv/bin/python scripts/podgotovit_audio.py запись.m4a
```

Приводит к моно 16 кГц — ровно то, с чем работают распознавалки; более высокое
качество исходника точности не добавляет. Понимает и видео. Заодно считает,
влезает ли результат в лимит телеграма, и если нет — с каким битрейтом
пересобрать. Расчёт идёт по фактическому размеру, а не по заданному битрейту:
opus переменный и на сложном материале превышает заданную цифру.

Дальше — расшифровка с `--diarize`. **Разделение по говорящим для встреч
обязательно:** без него выйдет простыня, из которой не понять, кто взял задачу.

Чем считать, зависит от машины: на Apple Silicon — `whispermlx` (форк whisperx
с движком `mlx-whisper`, работает через Metal), на ПК с NVIDIA — обычный
`whisperx`. У движка whisperx нет поддержки Metal, поэтому на Mac он считает
только процессором. Подробности в навыке `transkribirovat`.

Готовую расшифровку принимает субагент `protokol-vstrechi` и делает из неё
протокол. Это закрывает модуль протоколов встреч локально — без Microsoft
Graph и без согласований.

**Через телеграм** бот скачивает не больше 20 МБ: это ограничение Telegram.
Два часа речи укладываются примерно в 13 кбит/с, часовая запись в обычном
качестве — нет. Скрипт подготовки это считает.

## Личные задачи и напоминания

Задачи не по работе — свои инструменты и свой файл `personal/tasks.md`.
Он лежит **рядом с базой знаний, а не внутри неё**: в `brain/` его нашли бы
`search_memory` и `whoami`, а личному в рабочих ответах делать нечего.

| Инструмент | Что делает |
|---|---|
| `personal_tasks` | открытые задачи, просроченные и сегодняшние помечены |
| `add_personal_task` | добавить, срок необязателен |
| `close_personal_task` | закрыть по части текста |

Рабочие задачи сюда не кладутся: они в Execution Hub.

**Напоминание — не то же самое, что задача.** Задача лежит в списке и ждёт,
пока её спросят. Чтобы в нужный момент пришло уведомление, нужен бот
с расписанием: попроси телеграм-бота «напомни во вторник в 10 позвонить
в КИБ», и он заведёт себе будильник через свой инструмент `cron`.

Без запущенного бота напоминания не приходят — приходит только ответ
на вопрос «что у меня на сегодня».

## Почта

Чтение Gmail и выбор модели — **разные вещи**. Gemini как модель доступа
к почте не даёт: почту читает коннектор, и какой моделью ты при этом
пользуешься, неважно.

**В Claude Code** нужный плагин уже есть в списке, его остаётся настроить:
`/mcp` → `plugin:productivity:gmail` (в состоянии `not configured`).
Отдельной установки не требуется.

**В телеграм-боте** готового канала к Gmail нет, понадобился бы сторонний
MCP-сервер с доступом ко всему почтовому ящику. Для человека, отвечающего
за информационную безопасность, это отдельное решение, а не мелкая
настройка: такой сервер видит переписку целиком. Начать стоит с Claude Code,
где доступ остаётся между тобой и Google.

## Личные данные

Справочник серийных номеров, лицензий, тарифов и документов. Лежит **вне
репозитория** — по умолчанию `~/.brain-private/reference.md`, другой путь
задаётся переменной `BRAIN_REFERENCE`.

```bash
mkdir -p ~/.brain-private && chmod 700 ~/.brain-private
cp reference.example.md ~/.brain-private/reference.md
chmod 600 ~/.brain-private/reference.md
```

Разделы задаются строками `## Название`, инструмент `get_reference` возвращает
только совпавшие разделы, а не файл целиком.

**Почему не в `brain/`.** Во-первых, git-историю нельзя почистить задним
числом: однажды закоммиченный ИИН останется в ней навсегда, даже если удалить
строку. Во-вторых, всё из `brain/` попадает в контекст сессии через `whoami`
и `search_memory` — то есть уезжает к провайдеру модели при каждом запуске.
Справочник же читается только по прямому вопросу.

Сервер отказывается отдавать данные, если файл всё-таки оказался внутри
репозитория.

### Что сюда не кладут

| Класс | Примеры | Где хранить |
|---|---|---|
| Секреты | пароли, токены, API-ключи, 2FA | менеджер паролей, не здесь |
| Чужие персональные данные | ИИН и документы сотрудников, клиентов | кадровая система, не здесь |

Значение, полученное через `get_reference`, всё равно попадает в контекст
модели вместе с ответом. Для своих данных это обычно приемлемо, для чужих —
нет, и раздел «Границы» в `profile.md` это запрещает прямо.

## Структура базы

```
brain/
├── profile.md              кто я, как со мной работать, границы
├── people.md               кто есть кто, внешние контрагенты
├── projects/<проект>.md    цели, вехи, решения, блокеры, зависимости
├── log/ГГГГ-ММ.md          хронологическая лента, входящий буфер
└── sessions/               итоги сессий ИИ-клиентов
```

Лента — буфер. Устоявшееся переезжает в карточку проекта и оттуда удаляется,
иначе файл растёт без конца.

## Как править

Руками, как любой текст: в редакторе или прямо на GitHub кнопкой «edit».
История правок ведётся git, так что ничего не теряется и всегда видно,
что изменилось.

Другое расположение базы — переменная `BRAIN_DIR`.

## Заимствования

Часть приёмов взята из [BMAD-METHOD](https://github.com/bmad-code-org/BMAD-METHOD)
(bmad-code-org, MIT) — метода разработки на ИИ-агентах:

- правила опроса в `CLAUDE.md` и навыке `zapolnit-bazu` — из `bmad-project-context`,
  шаг «Interview the gaps»
- реестр изменений при обновлении карточки — оттуда же
- короткое меню методов с остановкой на подтверждение в `proverit-reshenie` —
  из `bmad-advanced-elicitation`; сами методы отобраны и переписаны под задачи
  руководителя разработки, каталог из 71 пункта целиком не переносился

Сам метод не заимствован: он про то, как вести разработку от идеи до кода
через агентов-ролей, а здесь роли заняты живыми людьми. Названия BMad —
товарный знак BMad Code, LLC, и в этом репозитории не используются.
